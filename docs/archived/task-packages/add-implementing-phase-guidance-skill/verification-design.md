# 验证策略

> **语言规则**：章节标题使用中文；正文默认使用中文；命令、状态值、YAML 键名、文件名与路径保持英文。

## 验证路径

- **计划路径**：子 Agent 对照审核矩阵逐项审核新 `implementing/SKILL.md` → 将审核结论呈现给人类审阅者 → 人类审阅者逐项反馈（同意/异议/补充）→ 综合两方结论写入 `evidence.md`
- **回退路径**：子 Agent 审核结论模糊（含"差不多""基本可以"等非二值判断）→ 回到本文件补充判定准则精度；人类审阅者异议 → 回到 implementing 修正对应章节；审核维度本身不完整 → 回到本文件补充审核维度
- **路径说明**：qualitative 双轨审核是本任务唯一可行的验证方式——验证对象是 SKILL.md 指令文档，无法用 pytest 或工作流脚本验证。审核矩阵覆盖 8 项交付结果，每个结果可追溯到 requirements.md 的对应条目

## 必需命令

本轮 `verify_by: qualitative`，无可执行命令。验证通过下述审核矩阵执行。

## 预期结果

- 子 Agent 逐项审核 16 条，每条产生二值结论（通过/不通过）+ 发现描述 + 严重程度（严重/一般/建议）+ 闭合状态
- 人类审阅者对 16 条逐项给出反馈（同意/异议/补充）
- 两方结论合并后，所有条目闭合且无严重未闭合项 → 通过；存在严重未闭合项 → 有条件通过，明确 follow-up 计划
- 最终结论（通过/有条件通过/不通过）由人类审阅者确定

## 风险接受

| 风险 | 接受理由 | 重新审查触发条件 |
|------|---------|----------------|
| 审核矩阵未覆盖"Skill 指令在实际 implementing 阶段的效果" | 本轮验证对象是 SKILL.md 文档本身的质量，不是运行时 agent 行为。运行时效果需在实际任务中观察 | 后续有 implementing 阶段 agent 行为退化的反馈时，回到本任务修正 |
| 子 Agent 审核可能遗漏微妙的措辞问题（如语气、歧义） | 人类审阅者逐项复审可以捕获大部分措辞问题。完全消除需多轮实际使用 | 人类审阅者发现审核矩阵未覆盖的问题类型时，补充审核维度 |
| Karpathy 准则的"翻译质量"无客观判定标准 | 准则内容本身是通用编程规范，翻译准确性的判断依赖人类审阅者对原文的理解 | 人类审阅者逐一对照 Karpathy 原文审核翻译准确性 |

## 验证执行计划

- **执行时机**：implementing 阶段完成（新 SKILL.md 写入后），立即在 verifying 阶段执行
- **子 Agent 执行**：启动独立子 Agent（`subagent_type: general-purpose`），将审核矩阵（16 条）、新 SKILL.md 全文交给子 Agent，子 Agent 逐项审核并输出结构化发现
- **人类审阅者执行**：子 Agent 审核结论呈现后，人类审阅者在 IDE 中打开新 SKILL.md，对照审核矩阵逐项给出反馈
- **执行环境**：无需特殊环境，审核仅读取文件内容
