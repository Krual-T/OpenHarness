## 目标
将任务包 `task-info.yaml` 模板中的 `id` 占位符从 `<DESIGN_ID>` 修正为 `TASK_ID`，让新建任务包模板表达当前协议使用的任务标识语义。

单一成功指标：目标模板文件中不再出现 `<DESIGN_ID>`，且 `id` 字段使用 `TASK_ID`。

## 问题陈述
目标用户是维护 OpenHarness 任务包协议与模板的协作者。核心场景是读取或复用 `skills/using-openharness/references/templates/task-package.task-info.yaml` 创建任务包元信息。

当前模板仍使用 `<DESIGN_ID>`，但仓库任务包语义使用任务标识；这个占位符会误导后续维护者把任务包编号理解成设计编号。现在修正可以避免错误继续复制到新任务包。

## 必须交付的结果
1. 修改 `skills/using-openharness/references/templates/task-package.task-info.yaml`：
   - 验收标准：`id:` 行从 `id: <DESIGN_ID>` 变为 `id: TASK_ID`。
2. 保持模板其他字段不变：
   - 验收标准：除目标占位符替换外，不引入格式、流程说明或字段语义变更。

## 非目标
- 不调整任务包创建流程、状态机或 CLI 行为。
- Counterexample：把所有任务包文档中的 `DESIGN_ID` 或其他历史命名一次性迁移，看起来相关，但不属于本轮。

## 约束
- 协议边界：只修改模板占位符，不改变任务包字段结构。
- 兼容性约束：不影响已有任务包实例。
- 依赖限制：不新增依赖。
- Cost cap：一次小型文本修改、一次定性检查、一次聚焦提交。
- 如果需要修改 CLI 生成逻辑或批量迁移现有任务包，就不再是本任务包范围。
