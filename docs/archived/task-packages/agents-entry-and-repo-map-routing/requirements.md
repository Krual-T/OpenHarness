# 需求

## 背景

OpenHarness 当前的 `AGENTS.md` 同时承担仓库事实地图、工作流约定、提交要求和信息输出规则。用户希望把它改成仓库级协作入口：只保留稳定入口路由、读取顺序、工程风格、Python 和 uv 约定、Reflection 规则、信息输出规则，并把详细仓库地图迁移到渐进式地图目录。

用户明确补充：原有提交要求必须保留。

## 问题陈述

后续协作者进入仓库时，`AGENTS.md` 应该先告诉他们如何读取上下文，而不是一次性复制完整仓库地图。现有文件把模块目录、运行时目录、任务包协议和提交要求混在同一层，后续地图细节继续增长时会让入口文件变重，也不利于按模块渐进读取。

同时，如果改写时漏掉提交要求，会破坏当前仓库的提交纪律：每轮可独立成立的改动要提交，提交前要更新 `pyproject.toml` 中的 `project.version`。

## 目标

完成后应成立以下事实：

- `AGENTS.md` 是仓库协作入口，不再承载完整仓库地图。
- 需要仓库地图时，协作者可以从 `docs/repo_map/MAP.md` 开始按层读取。
- `AGENTS.md` 保留提交要求，并明确提交前版本号更新规则。
- `docs/repo_map/` 下存在根层和贴合 OpenHarness 的主要入口地图，地图只做导航，不复制完整事实源内容。

## 交付物

- 重写 `AGENTS.md`，覆盖用户给出的入口规则，并保留原有提交要求。
- 新增 `docs/repo_map/MAP.md` 以及一层模块地图，覆盖长期文档、Python 源码、OpenHarness 技能、安装配置和测试入口。
- 新增或更新仓库地图写作反模式说明，供后续修改 `MAP.md` 前检查。
- 更新 `pyproject.toml` 补丁版本号，并提交本轮改动。

## 非目标

- 不迁移或重写历史任务包内容。
- 不改变 CLI、运行时工作流或测试逻辑。
- 不把所有源码目录逐文件展开成大型索引；地图保持导航用途。

## 约束

- 仓库内 Python 命令使用 `uv run ...`。
- 文档输出使用通俗中文；命令、状态值、YAML 键名、文件名和路径可以保留英文。
- 本轮若新增或更新地图，应遵守 `docs/anti-patterns/` 下的地图写作约束。
