# 接收代码审查

## 处理方式

1. 通读全部反馈，不要逐条反应
2. 用自己的话重述技术要求
3. 对照代码库和当前约束验证
4. 判断在本仓库中是否正确
5. 正确则实施，错误则用技术理由回应
6. 测试每个采纳的修改

## 不合适的回应

不要以表态性认同开头，也不要在验证前承诺修改。避免：
- "你说得对！" / "好主意！" / "我马上改"

合适的替代：重述技术问题、提出精准的澄清问题、验证后陈述结果。

## 处理外部审查者反馈

实施前检查：
1. 建议在此处技术上是否正确？
2. 是否会破坏现有行为？
3. 当前代码是否有这样写的理由？
4. 审查者是否有足够的上下文？

无法验证时，明确说明缺少什么证据。

## 何时拒绝

以下情况应拒绝反馈：
- 会破坏正常工作的行为
- 与仓库约束冲突
- 添加不需要的功能
- 技术上不正确
- 缺乏足够上下文来支撑变更

拒绝时用技术推理，不要带防御性。
