# 总体设计

> **语言规则**：章节标题使用中文；正文默认使用中文；命令、状态值、YAML 键名、文件名与路径保持英文。

## 系统边界

这轮设计覆盖哪些模块或接口，不覆盖哪些。覆盖和不覆盖都要落到具体模块、接口或职责边界，不接受只有抽象描述。

## 推荐结构

推荐方案的层次、模块划分、接口职责和关键约束。说清模块划分、依赖方向、接口职责，以及关键数据或状态模型落在哪个模块。

## 关键流程

主流程、状态流或信息流，标出关键失败信号可能出现的位置。如果安全、一致性、权限或兼容性约束会改变主路径，也一并说明。

## 阶段门禁

进入下一阶段前必须确定的硬性条件：关键约束、边界与接口决定、数据或状态模型、关键失败模式、降级或回退方向。必须是可判定的条件，不能只是把前文换个说法重写一遍。

## 取舍

方案的收益、代价、回退空间，以及为什么没选其他方向。至少比较一个可行备选方案，说明不选它的理由。优点和代价都要写。

## 推荐图示

如果某些结构关系仅靠文字容易歧义，说明推荐补哪些图（系统上下文图、模块图、主流程图等）。图补充文字，不替代文字中的边界、约束和例外说明。

## 反思

至少记录一次对备选方案、风险假设或验证影响的真实挑战，给出闭合结论（接受/拒绝/延期）。不能只写"考虑过"。
