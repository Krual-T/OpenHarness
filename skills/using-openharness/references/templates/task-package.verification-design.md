# 验证策略

> **语言规则**：章节标题使用中文；正文默认使用中文；命令、状态值、YAML 键名、文件名与路径保持英文。
>
> 本文件在实现前编写。定义验证策略——计划怎么验证、用什么命令、期望什么结果。实际验证执行和证据在 `verifying` 阶段写入 `evidence.md`。

## 验证路径

- **计划路径**：预期验证路径；命令保持英文原样。
- **回退路径**：主路径被阻塞时怎么处理，什么情况下不能宣称完成。
- **路径说明**：计划路径的限制、前提，以及为什么这条路径足够或不够。

## 必需命令

逐条列出本包要求执行的命令（英文原样）。明确标出哪些已执行、哪些未执行。

## 预期结果

执行后应观察到的结果，用于对比预期与实际。

## 可追溯性

需求、设计、验证证据之间的对应关系。列出核心需求与关键证据的对应关系。如有未覆盖的缺口，明确写出缺口和接受理由。

## 风险接受

本轮接受哪些残余风险、为什么可以接受，以及后续由什么事件或证据触发重新审查。

## 验证执行计划

何时执行、由谁执行、执行环境要求。实现完成后立即执行，不延迟到"后面再验"。

- 验证失败时：回到 `implementing` 修改代码，或回到 `verification_designing` 修正策略。
- `verify_by: qualitative` 时：审核由子 Agent 和人类审阅者双轨执行，两方结论均需写入 `evidence.md`；审核矩阵的判定准则必须对双方都明确无歧义。
